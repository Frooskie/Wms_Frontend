# Управление состоянием во фронтенде WMS

---

## 1. Общая концепция

В приложении используется гибридный подход:
- **Глобальное состояние** — NgRx SignalStore (для данных, общих для многих компонентов: пользователь, уведомления).
- **Локальное состояние** — простые сигналы (`signal()`, `computed()`) внутри компонентов.
- **Асинхронные данные** — `httpResource` / `rxResource` для загрузки с сервера.

Этот выбор обусловлен желанием использовать реактивность сигналов без излишнего бойлерплейта, характерного для классического NgRx.

---

## 2. SignalStore (глобальное)

Используется библиотека **@ngrx/signals**. Каждый стор — это фабрика, создаваемая через `signalStore()`.

### 2.1. Текущие сторы

1. **AuthStore** (`core/store/auth.store.ts`)
  - Состояние: `user`, `token`, `isLoading`, `error`.
  - Методы: `login()`, `register()`, `logout()`, `loadUserFromStorage()`, `clearError()`.
  - Используется в `AppComponent`, `LoginComponent`, `RegisterComponent` и в гарде.

2. **NotificationStore**
  - Состояние: список уведомлений, количество непрочитанных.
  - Методы: загрузка, отметка о прочтении, удаление.

### 2.2. Принципы работы с SignalStore

- Стор регистрируется с `{ providedIn: 'root' }`, поэтому доступен во всём приложении.
- Состояние обновляется через `patchState()` (иммутабельно).
- Селекторы — это просто сигналы (можно читать напрямую: `store.user()`).
- Методы могут быть асинхронными и вызывать сервисы.
- Эффекты (если понадобятся) реализуются через `rxEffect` или `withEffects`.

---

## 3. Локальное состояние (сигналы)

Каждый компонент может иметь собственные сигналы для:
- Состояния формы (значения полей, валидность).
- Параметров фильтрации и пагинации.
- Флагов загрузки (если не используется `httpResource`).
- Вычисляемых данных через `computed`.

---

## 4. Асинхронные данные — Resource API

Для загрузки данных с сервера используется `httpResource` (или `rxResource`). Они автоматически управляют состояниями `value`, `error`, `isLoading` и перезагружаются при изменении зависимостей.

Для мутаций (создание, обновление, удаление) используются прямые вызовы API-клиента, после чего вызывается `refetch()` у ресурса или обновляется сигнал-зависимость.

---

## 5. Почему не NgRx классический?

- Меньше шаблонного кода (не нужны действия, редукторы, эффекты).
- Отличная интеграция с Angular 22 и новым реактивным стеком.

---

## 6. Правила использования

- **Глобальный стор** — только для данных, используемых в разных частях приложения (пользователь, уведомления). Не хранить там данные, которые нужны только одному компоненту.
- **Локальные сигналы** — для всего остального.
- **Resource API** — для всех GET-запросов с пагинацией и фильтрацией. Для POST/PUT/DELETE использовать API-клиент напрямую.
- **Не использовать `subscribe`** — вместо этого читать сигналы в шаблонах или использовать `computed` для преобразований.
- **Избегать ручного unsubscribe** — сигналы и ресурсы автоматически управляют подписками.

---

## 7. Заключение

Гибридная модель управления состоянием, основанная на сигналах и SignalStore, обеспечивает высокую производительность, простоту и соответствие современным подходам Angular. Это позволяет легко масштабировать приложение и поддерживать код в чистоте.
