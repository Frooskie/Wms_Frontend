# Интеграция с бэкендом (API)

---

## 1. Генерация клиента

Для общения с бэкендом используется **NSwag** — инструмент, генерирующий TypeScript-клиент по OpenAPI-спецификации (файл `swagger.json`).

### 1.1. Команда генерации

```json
"generate-api": "nswag openapi2tsclient /input:swagger.json /output:src/app/core/api/wms-api.ts /template:Angular /httpClass:HttpClient /useSingletonProvider:true"
```
Выполняется через `npm run generate-api`.

### 1.2. Что генерируется

- Классы для всех DTO (запросы, ответы).
- Сервисы для каждого контроллера (например, `ProductService`, `BatchService`).
- Все методы возвращают `Observable<T>`.
- Готовые типы для параметров и тел запросов.

### 1.3. Правила работы с клиентом

- Файл `wms-api.ts` **не редактируется вручную** — все изменения перезаписываются при повторной генерации.
- Для удобства создаются обёрточные сервисы (например, `AuthService`), которые добавляют бизнес-логику (работа с localStorage, обработка ответов).
- В компонентах используется либо напрямую сгенерированный сервис, либо обёртка.

## 2. HTTP-интерсепторы

### 2.1. JWT-интерсептор (`core/interceptors/jwt.interceptor.ts`)

- Функциональный интерсептор.
- Добавляет заголовок `Authorization: Bearer <token>` к каждому запросу, кроме `/login` и `/register`.
- Токен читается из `AuthService.getToken()`.

### 2.2. Интерсептор ошибок

- Перехватывает ответы с ошибками (4xx, 5xx).
- Парсит `ProblemDetails` (RFC 7807) и показывает toast-уведомления через PrimeNG.
- Логирует ошибки в консоль и (опционально) в Sentry.

---

## 3. Работа с ресурсами (`httpResource`)

Все GET-запросы, особенно с пагинацией и фильтрацией, рекомендуется выполнять через `httpResource`. Это позволяет:
- Автоматически управлять состояниями загрузки и ошибок.
- Реактивно перезагружать данные при изменении параметров (сигналов).
- Интегрироваться с шаблонами через сигналы.

---

## 4. Мутации (POST, PUT, DELETE)

Для операций изменения данных напрямую вызываются методы сгенерированного клиента. После успешной мутации обычно требуется обновить список — для этого вызывается `refetch()` у соответствующего `httpResource`.

Пример (удаление товара):
```typescript
async deleteProduct(id: number): Promise<void> {
  try {
    await this.productService.delete(id).toPromise();
    this.productsResource.refetch(); // обновить список
  } catch (error) {
    // обработка ошибки
  }
}
```

---

## 5. Типизация ответов и запросов

Все DTO экспортируются из `wms-api.ts`. Используйте их для типизации переменных и аргументов. При необходимости можно создавать локальные интерфейсы для производных данных (например, объединение нескольких DTO), но старайтесь опираться на сгенерированные типы.

---

## 6. Прокси для разработки

Для локальной разработки настроен прокси-сервер (`proxy.conf.json`), который перенаправляет запросы на бэкенд, избегая CORS.
Пример конфигурации:
```json
{
  "/api": {
    "target": "https://localhost:5001",
    "secure": false,
    "changeOrigin": true,
    "logLevel": "debug"
  }
}
```
Запуск с прокси выполняется автоматически через `ng serve` (прописано в `angular.json`).

---

## 7. Обработка ошибок

- В будущем все ошибки API будут централизованно обрабатываться в интерсепторе.
- В компонентах мутаций рекомендуется использовать `try/catch` и показывать пользовательские сообщения.

---

## 8. Планы по улучшению

- Добавить кеширование ответов для редко изменяемых данных (справочники).
- Внедрить WebSocket для получения уведомлений в реальном времени.
- Реализовать повторные запросы при ошибках сети (retry logic).

## 9. Справочники по эндпоинтам

Полный список доступных эндпоинтов и их схем описан в `swagger.json`. Для быстрого ознакомления используйте сгенерированный клиент — все методы и типы документированы JSDoc-комментариями.

---

## 10. Заключение

Интеграция с бэкендом построена на генерации клиента по OpenAPI, что обеспечивает согласованность типов и упрощает разработку. Использование `httpResource` и функциональных интерсепторов делает код реактивным и чистым.
